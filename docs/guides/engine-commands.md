# 엔진 커맨드 보강

상류 filmcraft 에 없거나 모자라서 우리가 더하거나 바꾼 엔진 커맨드와 동작. 코드 1:1 대조 기준:
`packages/engine/vendor/filmcraft/crates/engine/src/{sh_commands.rs,commands.rs,lib.rs,color.rs}`, `crates/edit/src/lib.rs`,
`crates/render/src/lib.rs`, `crates/codecs/src/mp4.rs`, `crates/engine/src/graphics.rs`(newFromFile duration), `crates/engine/src/media_pool.rs`(Lottie 오프너),
`crates/media/src/lib.rs`(`at_size`), `crates/lottie`(이식한 Lottie 렌더러).
우리 커맨드는 `crates/engine/src/sh_commands.rs` 한 파일에 모여 있고(`commands.rs` 의 `build()` 끝에서 등록), 상류 커맨드를 고친
것은 해당 파일에 최소 diff 로 들어가 있다. 테스트: `crates/engine/src/sh_commands_tests.rs`(엔진), `crates/edit/src/tests.rs` 끝부분
(편집 대수), `crates/render/src/mixer_tests.rs` 끝부분(음정 유지), `packages/engine/tests/{transitions,napi,effects,speed-ratio,timestretch}.test.ts`(바인딩을 거친 기능).

## 트랜잭션 규칙

- `beginTransaction` 은 현재 undo 깊이를 마크로 기억한다. 그 뒤의 편집은 평소처럼 스냅샷을 쌓는다.
- 가장 바깥 `endTransaction` 이 마크 이후 스냅샷을 하나로 접는다: 첫 편집 전 스냅샷만 남기고 라벨을 트랜잭션 라벨로 바꾼다. 편집이 없었으면 단계가 생기지 않는다(`steps: 0`).
- 중첩: 안쪽 `begin` 은 깊이만 올리고 라벨은 무시한다. 안쪽 `end` 는 깊이만 내린다(`open: true`).
- `cancelTransaction` 은 깊이와 상관없이 첫 편집 전 상태로 되돌리고 트랜잭션을 닫는다. 되돌린 뒤에도 프로젝트는 "바뀜" 으로 표시된다(리비전 증가).
- 실패: 커맨드가 실패해도 트랜잭션은 자동으로 닫히지 않는다. 호출자가 `cancel`(전부 되돌림) 또는 `end`(부분 결과를 한 단계로) 를 고른다. `edit.transaction` 은 첫 실패에서 자동 `cancel`.
- 열린 동안 `edit.undo`/`edit.redo` 는 비활성. undo 한도(200)에 걸려 오래된 스냅샷이 밀리면 마크도 함께 내려간다(마크가 0 아래로 가면 남은 것만 접는다).
- `file.newProject`/`file.open` 처럼 history 를 통째로 바꾸는 커맨드는 트랜잭션을 버린다. 이후 `end` 는 "no transaction is open" 오류.
- 화면은 `packages/editor/src/engine/transaction.ts` 의 `withTransaction(bridge, label, body)` 로 쓴다: body 가 던지면 cancel 하고 다시 던진다. 쓰는 곳: 비율 변환(features/ratio), 텍스트 추가(features/text), 편집본 만들기·여러 항목 추가(features/onboarding).

## 남은 것

- 흔들림 분석 잡은 `effects.analyzeStabilizer` 로 걸었을 때만 돈다. `effects.apply warp_stabilizer` 를 바로 쓰면 예전처럼 첫 렌더가 동기로 분석한다(화면은 쓰지 않음).
- 속도 램프는 영상만 바꾼다. 소리까지 곡선을 따르게 하려면 오디오 믹서의 `source_time_at` 경로에 가변 리샘플이 필요하다.

- `sequence.inspect` 의 전환 `params` 는 아직 serde 태그 모양(`{"Float": 50.0}`)이다. 화면 `plainParams` 가 읽는다. 효과와 같은 `{kind, value}` 로 맞추는 것은 다음 라운드.
- 두 클립 사이 전환 길이를 클립의 남은 소스(핸들)로 제한하지 않는다(상류도 하지 않음). 렌더는 범위를 잘라 그린다.
- 상류 테스트 중 `shortcuts_tests::assign_reassigns_conflicts_and_undoes`(기본 단축키 충돌 수)와 `export_tests::every_builtin_preset_exports_and_ffprobe_confirms`(이 환경의 ffprobe 가 APV 를 모름)는 이 작업과 무관하게 실패한다.
